# 會議停止後的處理時間

最終修正版 `timed-3`：同一份 **48 分 4.45 秒**原始雙軌音訊以 1 倍速重播，原定音訊結束至全部結果保存 **7.986 秒**。計時與結構通過；已知三項交辦、期限及各輸出時間一致性核對通過。完整條件與證據見本文最後一節。

驗收目標：48 分鐘會議按下停止後，10 秒內完成逐字稿、說話者辨識、整理版、依人彙整、摘要及待辦。背景草稿、只完成轉錄、失敗後提早返回，都不算完成。效能結果與內容品質必須分別驗證。

## 錄音期間的處理

- 使用者選擇 hosted 語音辨識優先、本機說話者模型優先、雲端 LLM 時，建立每場獨立的預處理 session。仍使用原本選擇的服務與模型。本機優先不會被跳過；錄音中設定或所用金鑰改變，舊 session 停止啟動新工作，停止後由最新設定接手。
- 每 2 秒檢查音訊，以約 20–30 秒、兩軌共同安靜處切段，兩軌並行轉錄。失敗保留成功前綴並退避重試；停止後再從未完成處補上。
- 同一 Nemotron `.offline` session 持續處理兩軌，各軌保持自己的 speaker history，共用的推論緩衝區在同一 actor 序列使用。Snapshot 不呼叫 finish；真正停止時才 flush lookahead。
- WeSpeaker 依 `(cluster, start sample, end sample)` 快取各軌聲紋片段，每次只計算新片段。延長或重疊造成的舊尾段會失效；centroid 只納入當下片段，沿用原有語音長度門檻與正規化方式。直接讀取所需音訊範圍，不在停止時重新轉換整場檔案。
- 語音切點對齊回音能量統計的 50ms 格點，避免多片串接累積偏移；遠端靜音、沒有執行回音消除的片段，也保留麥克風實際能量，避免整場 speaker cluster 被誤判為回音。
- 逐字對齊每段最多約 20 秒（不拆單一 word），避免連續發言變成無法切分的長篇。只把說話者水位以前、已封閉的逐字稿前綴交給背景 LLM；仍可變動的尾段留到下一輪。
- 背景名稱推測、整理、依人彙整、摘要並行，前一輪未完成時只保留最新前綴，完成後自動接續，不堆積過時 snapshot。草稿不寫入會議資料庫。
- 同一 provider instance 以完整 system、input、schema 快取通過解析與驗證的結果；同輸入的進行中請求共用。來源 ID、說話者、前文、詞彙、重點或日期改變會失效。錄音用整理分塊上限改為 300 字，跨分塊保留前 6 句語境，輸出來源僅限本塊；原先非錄音流程維持既有設定。
- 摘要與待辦更新仍送完整原始來源及上次摘要；當來源是相同前綴的延長時，只生成刪除、替換與新增的差異。來源或說話者改動則完整重算。差異的索引、來源、負責人與期限必須合法，格式不合法時回退完整生成，網路或授權錯誤仍回報失敗，不拿舊摘要假裝完成。
- 完整摘要與增量更新都須保留提議的條件與承諾程度；「下次會議前」完成的待辦，後文確認同場會議日期與時刻後，要更新完整期限並引用任務、日期、時間的來源。未確認的時分不補猜。
- 依人彙整亦使用完整原始來源與上次彙整，僅生成各人的刪除、替換與新增重點。每次仍檢查前綴、說話者、語言與詞彙是否相容；不相容或差異格式不合法時完整重算，較舊的非同步結果不能覆蓋較新的結果。

## 停止時的處理

停止錄音、等待目前音訊讀取完成、搬檔、補最後一段轉錄與模型 lookahead，然後用完整最終來源重新對齊、比對聲紋。正常 pipeline 再完成所有 LLM 輸出，命中快取的部分直接重用，變動部分重新處理。只有正常 pipeline 成功保存全部結果才標示完成。

預處理失敗時保留原本的完整處理退路。匯入、復原、本機優先、只靠轉錄服務分群的設定，無法回溯取得錄音期間的預處理成果。服務延遲、排隊、重試，以及停止前尚未追上的工作都會增加最終等待。

錄音中會增加 LLM 請求與輸入 token；短語音分段亦增加請求數。快取能避免重複生成穩定的整理內容，但不代表供應商帳單不增加。沒有切換使用者選用的模型來取得較快數字。

## 量測與驗證

本文保留歷史量測結果。當時使用的 App debug 重播入口與操作文件已移除，以下模式及報告欄位僅用於解讀既有證據，不是目前可執行的重現步驟，也不代表清理後版本已重新量測。當時 `timed` 只按真實時間釋出音訊，計時由實際 `CaptureController.stop()` 呼叫前開始。`accelerated` 是診斷，給背景工作額外準備時間，最後 20 秒音訊仍在停止呼叫內才釋出；它不能證明真實錄音符合 10 秒。
